# 发布流水线部署步骤（Jenkins → GitLab → Harbor → prod）

> 2026-09-24 · 供手动操作的设计文档。前置状态：Jenkins（ns jenkins，devops-m1）/ GitLab CE 17.9.1（ns gitlab，devops-m1）/ Harbor 2.15.2（ns harbor，devops-w1）已就绪，统一入口 ingress-nginx NodePort 32037（EIP 123.58.219.112）。
> 前置：本机及所有操作机 hosts 已加 `123.58.219.112 jenkins.devops.local gitlab.devops.local harbor.devops.local`
> 凭据：GitLab root / `Dev0ps#2026` · Harbor admin / `Harbor12345`

```
git push → GitLab webhook → Jenkins 流水线
                                  ├─ kaniko pod 构建 + push 镜像 → Harbor (demo/demo-app:TAG)
                                  └─ kubectl apply 到 prod 集群 ns demo → Gateway API/NodePort 访问
```

关键前提（都是踩过的坑，见《环境搭建.md》）：

1. **GitLab API 无密码 Basic Auth**（16.0+ 移除），所有 API/CI 集成必须用 PAT
2. **Harbor 无 TLS**：客户端 containerd/docker 必须配 insecure registry，且必须用域名（externalURL 钉死 `harbor.devops.local:32037`）
3. prod 节点不在 devops 集群，**必须显式配 hosts + containerd http 拉取**才能用 Harbor 镜像

---

## 第一步：内网域名解析（devops 集群 CoreDNS）

集群内组件（GitLab webhook 回调 Jenkins、Jenkins agent git clone、kaniko push）都用 `*.devops.local:32037` 域名，而域名当前只在外部 hosts 里。给 devops 集群 CoreDNS 加 hosts 块，指到 master 内网 IP `10.7.6.245`（ingress-nginx NodePort 在所有节点都通，内网 IP 即可）。

编辑 Corefile（注意 `reload` 插件已默认开启，改完约 30s 自动生效，不用重启 pod）：

```bash
kubectl --context devops -n kube-system get cm coredns -o jsonpath='{.data.Corefile}'
```

在 `ready` 之后插入 hosts 块（用 `kubectl edit cm coredns -n kube-system` 或 patch）：

```text
    hosts {
       10.7.6.245 jenkins.devops.local gitlab.devops.local harbor.devops.local
       fallthrough
    }
```

验证（任一 namespace 起临时 pod）：

```bash
kubectl --context devops run dns-check --rm -i --restart=Never --image=busybox:1.36 --command \
  -- sh -c 'nslookup gitlab.devops.local && wget -q -O- -T 5 http://gitlab.devops.local:32037/users/sign_in | head -c 50'
# 期望：Address 10.7.6.245，wget 返回 HTML
```

> 多节点集群（prod）同样做法，hosts IP 换成 prod master 内网 IP。
> 坑：Corefile 改坏了 CoreDNS 全挂，先 `get cm -o yaml` 备份再改。

## 第四步：prod 集群准备

### 1. 授权 SA（最小权限）

```bash
kubectl --context prod apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: demo
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: jenkins-deployer
  namespace: demo
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: jenkins-deployer-edit
  namespace: demo
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: edit
subjects:
  - kind: ServiceAccount
    name: jenkins-deployer
    namespace: demo
EOF
```

### 2. 生成长期 kubeconfig（Jenkins 用）

```bash
# SA token secret（k8s 1.31 用 expirable token）
kubectl --context prod -n demo apply -f - <<'EOF'
apiVersion: v1
kind: Secret
metadata:
  name: jenkins-deployer-token
  namespace: demo
  annotations:
    kubernetes.io/service-account.name: jenkins-deployer
type: kubernetes.io/service-account-token
EOF

TOKEN=$(kubectl --context prod -n demo get secret jenkins-deployer-token -o jsonpath='{.data.token}' | base64 -d)
CA=$(kubectl --context prod -n demo get secret jenkins-deployer-token -o jsonpath='{.data.ca\.crt}')

# prod apiserver 内网地址（master 10.7.94.38:6443，按实际改）
cat > kubeconfig-prod <<EOF
apiVersion: v1
kind: Config
clusters:
- name: prod
  cluster:
    server: https://10.7.94.38:6443
    certificate-authority-data: ${CA}
contexts:
- name: jenkins-deployer@prod
  context:
    cluster: prod
    user: jenkins-deployer
current-context: jenkins-deployer@prod
users:
- name: jenkins-deployer
  user:
    token: ${TOKEN}
EOF

# 验证：只能看 demo，不能看 kube-system
KUBECONFIG=kubeconfig-prod kubectl get ns demo
KUBECONFIG=kubeconfig-prod kubectl get pods -n demo
KUBECONFIG=kubeconfig-prod kubectl get pods -n kube-system   # 应 Forbidden
```

> 坑：`10.7.94.38:6443` 是内网地址，**只有 devops 集群内的 pod（Jenkins agent）能直达**。本地 Mac 只能通过隧道 `127.0.0.1:26443` 访问 prod，kubeconfig-prod 拿到本机直接跑 `kubectl` 会超时。已实测：devops 集群内 pod → prod-m1:6443 连通；Mac → 10.7.94.38:6443 超时。
> 本机想验证这份 kubeconfig，用 devops 集群临时 pod 代跑：
>
> ```bash
> kubectl --context devops run kubectl-img --rm -i --restart=Never \
>   --image=bitnami/kubectl:1.31 --overrides="$(cat kubeconfig-prod.json)" \
>   -- kubectl get pods -n demo
> ```
>
> 或者干脆跳过本机验证——直接交给 Jenkins 流水线跑 deploy 阶段，失败再看构建日志。

### 3. prod 节点拉取 Harbor 镜像（三节点都要）

无 TLS + 域名不在公网 DNS，containerd 必须显式指路。每个 prod 节点：

```bash
# hosts（prod 节点访问 devops 内网走 10.7.6.245）
echo '10.7.6.245 harbor.devops.local' >> /etc/hosts

# containerd 明文 http 拉取 + 跳过端口 32037 的证书校验
mkdir -p /etc/containerd/certs.d/harbor.devops.local:32037
cat > /etc/containerd/certs.d/harbor.devops.local:32037/hosts.toml <<'EOF'
server = "https://harbor.devops.local:32037"

[host."https://harbor.devops.local:32037"]
  capabilities = ["pull", "resolve"]
  skip_verify = true
  override_path = false
EOF

systemctl restart containerd
```

验证（节点上）：

```bash
crictl pull harbor.devops.local:32037/demo/demo-app:v1   # 推送第一个镜像后测
```

> 坑：hosts.toml 的 server 也可写 http://，但配合 skip_verify 用 https 表达式更稳。若 config.toml 没开 `config_path`，需要在 /etc/containerd/config.toml 的 [plugins."io.containerd.grpc.v1.cri".registry] 下加 `config_path = "/etc/containerd/certs.d"` 再重启。
> prod ns demo 里业务 Pod 拉私有镜像还需 imagePullSecrets 或项目 robot 的 dockerconfigjson Secret：

```bash
kubectl --context prod -n demo create secret docker-registry harbor-pull \
  --docker-server=harbor.devops.local:32037 \
  --docker-username='demo+prod-pull' --docker-password='<prod-pull secret>'
# deploy.yaml spec.template.spec 加 imagePullSecrets: [{name: harbor-pull}]
```

## 第五步：Jenkins 配置

### 1. 凭据（Manage Jenkins → Credentials）

| ID | 类型 | 值 |
|---|---|---|
| `gitlab-root-pat` | Secret text | PAT（glpat-...） |
| `harbor-push` | Username with password | `demo+jenkins-push` / robot secret |
| `prod-kubeconfig` | Secret file | 上一步的 kubeconfig-prod |

### 2. GitLab Connection（GitLab 插件）

Manage Jenkins → System → GitLab：
- Connection name: `gitlab-local`
- GitLab host URL: `http://gitlab.devops.local:32037`（Jenkins 控制台容器内需能解析——走 CoreDNS hosts 块，已完成）
- Credentials: `gitlab-root-pat`
- Test Connection 应返回 Success

### 3. Agent / 构建方式

本环境 Jenkins 是 chart 装的（内置 kubernetes 插件）。两种方式选一：

**方式 A（简单）**：Jenkinsfile 直接 `podTemplate`，流水线里起 kaniko pod 构建。无需预配 agent 池。

**方式 B（正式）**：Manage Jenkins → Nodes → Pod Templates 预定义 kaniko/maven 模板。

推荐 A，模板写在 Jenkinsfile 里随仓库走。

### 4. Jenkinsfile（完整版，放仓库根目录）

```groovy
def tag = "b${env.BUILD_NUMBER}-${sh(script: 'git rev-parse --short HEAD', returnStdout: true).trim()}"

pipeline {
  agent any
  options { timestamps(); disableConcurrentBuilds() }
  environment {
    HARBOR = 'harbor.devops.local:32037'
    PROJECT = 'demo'
    APP = 'demo-app'
  }
  stages {
    stage('Build & Push (kaniko)') {
      steps {
        script {
          // Secret file 凭据必须挂进 pod，kaniko 才能认证
          podTemplate(name: 'kaniko', label: 'kaniko',
              containers: [
                containerTemplate(name: 'kaniko', image: 'gcr.io/kaniko-project/executor:debug',
                  command: ['sleep'], args: ['9999999'],
                  ttyEnabled: true)
              ],
              volumes: [
                secretVolume(secretName: 'harbor-push-config', mountPath: '/kaniko/.docker')
              ]) {
            node('kaniko') {
              container('kaniko') {
                sh """
                  /kaniko/executor \
                    --context=git://gitlab.devops.local:32037/root/demo-app.git#refs/heads/main \
                    --destination=${HARBOR}/${PROJECT}/${APP}:${tag} \
                    --insecure --skip-tls-verify --cache=false
                """
              }
            }
          }
        }
      }
    }
    stage('Deploy to prod') {
      steps {
        withCredentials([file(credentialsId: 'prod-kubeconfig', variable: 'KCFG')]) {
          sh '''
            sed "s|BUILD_PLACEHOLDER|'${tag}'|" k8s/deploy.yaml > deploy-apply.yaml
            KUBECONFIG=$KCFG kubectl apply -f deploy-apply.yaml
            KUBECONFIG=$KCFG kubectl -n demo set image deployment/demo-app demo-app=${HARBOR}/${PROJECT}/${APP}:${tag}
            KUBECONFIG=$KCFG kubectl -n demo rollout status deployment/demo-app --timeout=180s
          '''
        }
      }
    }
  }
}
```

kaniko 认证 Secret（jenkins ns 里建一次）：

```bash
# 先生成 dockerconfigjson
kubectl --context devops -n jenkins create secret docker-registry harbor-push-config \
  --docker-server=harbor.devops.local:32037 \
  --docker-username='demo+jenkins-push' --docker-password='<robot secret>'
```

> 坑：kaniko `--insecure` 必须加（Harbor 无 TLS）；`--destination` 必须带 `:32037` 端口；Jenkinsfile 里 sed 替换镜像 tag 时 `deploy.yaml` 的 image 字段要用 `BUILD_PLACEHOLDER` 占位。
> 坑：kaniko 需要仓库内容，`--context=git://` 会再 clone 一次。更简单的做法是流水线先 checkout 再用 `--context=$WORKSPACE`，但 pod 间共享 workspace 要 PVC/共享卷，git context 免共享卷。

### 5. GitLab webhook（触发构建）

GitLab demo-app → Settings → Webhooks：
- URL: `http://jenkins.devops.local:32037/project/demo-app`
- Trigger: Push events
- Secret token: 自定义字符串（与 Jenkins job 的一致）

> URL 路径 `/project/<job名>` 是 GitLab 插件约定。GitLab 服务器要能解析 jenkins.devops.local——CoreDNS hosts 块已覆盖。
> 界面添加后点 Test → Push events，应返回 HTTP 200。

### 6. Jenkins job

- New Item → Pipeline，名 `demo-app`（与 webhook URL 一致）
- Build Triggers：勾 **Build when a change is pushed to GitLab**（GitLab Connection 选 gitlab-local，Secret token 与 webhook 一致）
- Pipeline → Definition: Pipeline script from SCM
  - SCM: Git，URL `http://gitlab.devops.local:32037/root/demo-app.git`
  - Credentials: 建一个 Username with password（root / PAT 作为密码）——http clone 私仓必须认证
  - Branch: main，Script Path: Jenkinsfile

排障速查：

| 症状 | 原因 |
|---|---|
| webhook Test 403/404 | Jenkins job 名与 URL 不一致；或 GitLab 解析不了 jenkins.devops.local（查 CoreDNS） |
| kaniko 报 unauthorized | robot secret 错 / 用户名没带 `demo+` 前缀 / secret 没挂到 /kaniko/.docker |
| kaniko 报 x509 | 没加 `--insecure` |
| prod ImagePullBackOff | 节点 hosts / certs.d hosts.toml 未配；或没 imagePullSecrets |
| deploy 阶段 Forbidden | kubeconfig SA 权限只限 ns demo，检查 RoleBinding |
