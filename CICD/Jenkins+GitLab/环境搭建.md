# 一、Jenkins 安装步骤

## 1. 前置条件（已具备）

- devops 集群 ingress-nginx（baremetal NodePort 32037/31955）已部署
- local-path-provisioner 为默认 SC（落盘 `/data/local-path-provisioner`，devops-m1 492G 可用）
- devops-m1 是 master，带 `control-plane:NoSchedule` 污点 → values 需 toleration

## 2. 安装

```bash
helm repo add jenkins https://charts.jenkins.io
helm repo update jenkins

helm upgrade --install jenkins jenkins/jenkins \
  -n jenkins --create-namespace \
  -f jenkins-values.yaml
```

values 要点（完整见 `jenkins-values.yaml`）：

| 项 | 值 | 原因 |
|---|---|---|
| serviceType | ClusterIP | 走 ingress-nginx NodePort 暴露 |
| ingress | nginx / jenkins.devops.local | 与 GitLab/Harbor 统一入口方式 |
| nodeSelector | devops-m1 | local PV 与节点绑定，必须固定 |
| tolerations | control-plane:NoSchedule | master 有污点，不容忍则 Pending |
| image | **用 chart 默认（2.568.3）** | 见下方踩坑 #1 |
| additionalPlugins | gitlab-plugin / pipeline-stage-view / docker-workflow / blueocean | 只补 chart 默认没有的 |
| javaOpts | `"-Duser.timezone=Asia/Shanghai"` | 必须字符串；时区 |
| persistence | local-path / 100Gi | 默认 SC 自动供给 |

## 3. 验证

```bash
# pod 2/2 Running（init 下载 116 个插件需几分钟）
kubectl --context devops -n jenkins get pods

# admin 密码
kubectl --context devops -n jenkins exec svc/jenkins -c jenkins -- \
  cat /run/secrets/additional/chart-admin-password

# ingress 冒烟（ingress-nginx NodePort 32037）
curl -H "Host: jenkins.devops.local" http://123.58.219.112:32037/login -I   # 200
```

浏览器访问：本机 hosts 加 `123.58.219.112 jenkins.devops.local`，开 `http://jenkins.devops.local:32037`。

## 4. 踩坑记录（重要）

1. **不要钉死旧 LTS 镜像 tag。** chart 5.9.63 默认插件版本按 Jenkins 2.568.3 解析，钉 `2.492.3-lts` 会导致默认插件要求 Jenkins≥2.504.3，`install-plugins` init 容器每次启动失败 → pod 反复重建。用 chart 默认镜像即可。
2. **additionalPlugins 不能与 chart 默认 installPlugins 重复**（kubernetes/git/workflow-aggregator/credentials-binding/timestamper 等已内置），重复会 helm 模板报错。
3. **javaOpts 必须是字符串**，写成列表 helm 报错。
4. **插件下载进 emptyDir，不持久化**：每次 pod 重建都重新下载 116 个插件（updates.jenkins.io 从香港慢，偶有 429/卡顿，init 有 3 次重试，一般能自愈）。→ 不要随便删 pod；改 values 后 `helm upgrade` 不会滚动 StatefulSet pod，需手动 `kubectl delete pod jenkins-0`，代价就是全量重下插件。
5. **master 污点**：nodeSelector 钉 devops-m1 必须配 toleration，否则 Pending。
6. `kubectl rollout status` 在 StatefulSet init 阶段会提前报 "successfully rolled out"，不可信；以 `get pods` 2/2 为准。

## 5. 状态快照（安装完成时）

- Release `jenkins` rev 2，StatefulSet jenkins-0（2.568.3-jdk21）
- PVC 100Gi local-path，落盘 devops-m1 `/data/local-path-provisioner/pvc-8699ebab-*`
- Ingress: jenkins.devops.local → jenkins:8080（nginx class，NodePort 32037）
- admin 密码存 Secret `jenkins`，上述命令随时可取

# 二、GitLab CE 安装步骤（Omnibus 单容器）

## 1. 方案选型

**不用官方 `gitlab/gitlab` Helm chart**：它要拖 cert-manager + 独立 nginx-ingress + 10 来个 pod，对裸机实验环境太重。
**用 Omnibus 单容器**（StatefulSet + `GITLAB_OMNIBUS_CONFIG` 环境变量注入配置）：一个 pod 全家桶，最接近生产 VM 装机体验，排错面小。

## 2. 安装

```bash
kubectl --context devops apply -f gitlab-omnibus.yaml
```

manifest 要点（完整见 `gitlab-omnibus.yaml`）：

| 项 | 值 | 原因 |
|---|---|---|
| image | gitlab/gitlab-ce:17.9.1-ce.0 | CE 最新稳定大版本 |
| GITLAB_OMNIBUS_CONFIG | external_url `http://gitlab.devops.local:32037` | 生成 clone/CI 回调 URL 带对端口 |
| | `nginx['listen_port'] = 80`（必加） | external_url 带端口时 nginx 默认监听 32037，Service/Ingress/探针全走 80 → 不加则全 503/探针失败 |
| | gitlab_ssh_host=123.58.219.112, ssh_port=30222 | SSH clone 走 EIP NodePort |
| | puma worker=2, sidekiq concurrency=10 | 压缩内存（与 Jenkins 共存 32G 裸机） |
| | prometheus_monitoring=false | 自带监控全家桶太重，禁用 |
| | `monitoring_whitelist` 加节点 IP（必加） | health 端点默认只放行 127.0.0.0/8，kubelet 探针来自节点 IP → 404 → readiness 永不过 → ingress 一直 503（见踩坑 #10） |
| nodeSelector + tolerations | devops-m1 + control-plane | local PV 绑定 + master 污点 |
| initContainer | busybox **只 chown /etc/gitlab** | /var/opt/gitlab 属主由 chef 按服务管理，绝不能整树 chown（见踩坑 #9） |
| volumes | data=PVC 100Gi, config=emptyDir | 数据持久化；gitlab.rb 不落盘（配置全靠环境变量） |
| Service | http 80（给 Ingress）+ ssh 22→NodePort 30222 | SSH 需要额外 NodePort |
| Ingress | gitlab.devops.local → gitlab:80 | **manifest 里带**，含 body-size=0 / request-buffering=off 注解（git push 大对象必需） |
| 探针 | readiness 180s 延迟 / liveness 300s 延迟，failureThreshold 30 | 首次 reconfigure 要几分钟，避免误杀 |

## 3. 验证

```bash
# pod 1/1 Running（首次 reconfigure 约 4-6 分钟，期间 0/1 Running 是正常的）
kubectl --context devops -n gitlab get pod gitlab-0

# root 初始密码（首次启动自动生成，存于 emptyDir——务必在重建 pod 前改掉）
kubectl --context devops -n gitlab exec gitlab-0 -- cat /etc/gitlab/initial_root_password

# ingress 冒烟
curl -H "Host: gitlab.devops.local" http://123.58.219.112:32037/users/sign_in -I   # 200
```

root 密码统一改为 `Dev0ps#2026`（与 Secret `gitlab-root-password` 一致）：

```bash
kubectl --context devops -n gitlab exec gitlab-0 -c gitlab -- gitlab-rails runner \
  'u = User.find_by(username: "root"); u.password = "Dev0ps#2026"; u.password_confirmation = "Dev0ps#2026"; u.save!'
```

## 4. 踩坑记录（重要）

1. **external_url 带端口 → nginx 监听该端口（最大坑）。** `external_url 'http://gitlab.devops.local:32037'` 会让容器内 nginx 监听 32037，而 Service/Ingress/探针全打 80 → 探针 connection refused、Ingress 503。必须加：
   ```ruby
   nginx['listen_port'] = 80
   nginx['listen_https'] = false   # external_url 是 http 时本来就不开 443，显式写上稳妥
   ```
2. **root 密码不能含 "gitlab" 等常用词**：密码强度校验报 "must not contain commonly used combinations of words and letters"，`Gitlab@2026` 被拒，用 `Dev0ps#2026`。
3. **镜像 2.5GB，香港拉 auth.docker.io 偶发 TLS handshake timeout。** kubelet ImagePullBackOff 重试间隔指数退避很长，等不起 → 上节点 `crictl pull` 循环重试（30 次 × 20s），成功后删 pod 让它用缓存。
4. **`/etc/gitlab` 是 emptyDir**：`initial_root_password`、gitlab-secrets 都不持久化。数据在 PVC（/var/opt/gitlab）里不受影响，但**首次启动后第一件事就是把 root 密码改成已知值**，否则 pod 一重建初始密码就没了（此时只能走 rails runner 重置）。
5. **GITLAB_OMNIBUS_CONFIG 是唯一配置入口**：改配置 = 改 manifest + 重建 pod。不要指望 exec 进去改 gitlab.rb——emptyDir，重启即失。另注意：**改了 StatefulSet 模板后 controller 不一定马上滚动 pod**（本次 apply 后 2 分钟无动作），手动 `kubectl delete pod gitlab-0` 触发即可。
6. **Ingress 注解必须加** `proxy-body-size: "0"` + `proxy-request-buffering: "off"`：ingress-nginx 默认 body 限制 1m，git push 超 1MB 直接 413。
7. **首次 reconfigure 期间 0/1 Running 是正常的**（puma/sidekiq/DB 逐个起来，约 4-6 分钟），别误删 pod；探针 initialDelay 已按此调大。
8. **SSH 与 Web 分开暴露**：Web 走 Ingress(32037)，SSH 必须单独 NodePort（30222），external_url 只管 Web。
9. **initContainer 绝不能 `chown -R 998:998 /var/opt/gitlab`。** Omnibus 各服务用独立 uid：git=998 / gitlab-redis=997 / gitlab-psql=996 / gitlab-www=999。首次装机 chef 会按各服务属主初始化数据目录，但 pod 重建时整树 chown 成 git 会打爆属主：postgresql/redis 起不来（`PG_VERSION: Permission denied`，0600 文件），`gitlab-ctl status` 显示 `down: postgresql/redis ... want up`，puma 502。修法：无数据直接删 PVC 重装（本次采用）；有数据则 exec 按服务改回（`chown -R 996:996 /var/opt/gitlab/postgresql; chown -R 997:997 /var/opt/gitlab/redis; chown -R 999:999 /var/opt/gitlab/nginx`）再 `gitlab-ctl restart postgresql redis`。initContainer 只 chown /etc/gitlab（emptyDir）。
10. **health 端点 IP 白名单（`gitlab_rails['monitoring_whitelist']`）默认只放行 127.0.0.0/8。** kubelet 探针来自节点 IP（devops-m1=10.7.6.245）→ `/-/readiness`、`/-/liveness` 一律 404 → readiness 永不过 → Service 无 endpoints → **ingress 一直 503，但 `kubectl exec` 内部 curl localhost 全 200**，极易误判"服务正常，网络问题"。判别法：`kubectl get endpoints gitlab` 为空 + workhorse access log 里 kube-probe 请求 404 = 白名单问题。修法：`gitlab_rails['monitoring_whitelist'] = ['127.0.0.0/8', '::1/128', '10.7.6.245']`（加节点 IP；多节点加网段如 10.7.0.0/16）。
11. **GitLab 16.0+ 移除了 API 密码 Basic Auth**：`curl -u root:pass /api/v4/...` 一律 401（连正确密码也 401），不是密码错也不是故障。密码只用于 Web 登录和 oauth password grant（`POST /oauth/token`）。**API/CI 集成必须用 PAT**：root 建议界面生成 `glpat-` token；或 rails 造（PAT 必须带 `expires_at`，nil 会被校验拒绝）。验证密码是否正确的姿势：oauth grant 或 `User#valid_password?`，别用 Basic Auth 试。

- PVC gitlab-data 100Gi local-path，落盘 devops-m1 `/data/local-path-provisioner/pvc-d245fa23-*`（重装修复属主问题后）

# 三、Harbor 安装步骤

## 1. 安装

```bash
helm repo add harbor https://helm.goharbor.io
helm repo update harbor

helm upgrade --install harbor harbor/harbor \
  -n harbor --create-namespace \
  -f harbor-values.yaml
```

values 要点（完整见 `harbor-values.yaml`）：

| 项 | 值 | 原因 |
|---|---|---|
| expose.type | ingress（nginx class，无 TLS） | 裸机暂无证书，先 http；统一 *.devops.local 入口 |
| externalURL | `http://harbor.devops.local:32037` | UI 上 docker login/push 命令带对地址（否则默认 80） |
| persistence | registry 100Gi / database 10Gi / redis 5Gi / trivy 10Gi，全 local-path | 默认 SC；registry 是大头 |
| nodeSelector | devops-w1 | local PV 绑节点，显式钉死（cluster-plan 5.1） |
| harborAdminPassword | Harbor12345 | 显式写进 values，不依赖随机 secret |

## 2. 验证

```bash
# 7 个 pod 全 Ready（core/jobservice/portal/registry/registryctl/database/redis/trivy）
kubectl --context devops -n harbor get pods

# portal + API 冒烟
curl -H "Host: harbor.devops.local" http://123.58.219.112:32037/ -I                     # 200
curl -H "Host: harbor.devops.local" http://123.58.219.112:32037/api/v2.0/users/current \
  -u admin:Harbor12345 -I                                                              # 200
```

## 3. 踩坑记录（重要）

1. **jobservice 启动即 panic 循环重启**：core 没起来时 jobservice 拿不到配置会 panic，core Ready 后自愈，**不用管**（一般 3 次内收敛）。
2. **admin 密码不写 values 会随机生成**在 Secret `harbor-core` 的 `HARBOR_ADMIN_PASSWORD`。要改成已知值不能只改 values——helm 不会更新已有 secret，需：
   ```bash
   kubectl --context devops -n harbor delete secret harbor-core
   helm upgrade harbor harbor/harbor -n harbor -f harbor-values.yaml --reuse-values
   ```
   （secret 重建 + upgrade 触发 pod 重建，密码生效）
3. **PVC 一直 Pending**：local-path 是 WaitForFirstConsumer，第一个消费者 pod 调度后才供给，正常现象。
4. **registry pod 长时间 ContainerCreating**：registryctl 镜像（55MB）还在拉。w1 出香港带宽小，耐心或上节点 `crictl pull` 预热。
5. **externalURL 必须带 :32037**：否则 UI 复制出来的 docker push 命令缺端口，push 404。
